## 3. Краткое описание REST и принципов REST

REST — архитектурный стиль для web-приложений, в котором данные представлены в виде ресурсов. Каждый ресурс имеет URI, а действия над ресурсом выполняются стандартными HTTP-методами:

- `GET` — получение ресурса или списка ресурсов;
- `POST` — создание нового ресурса;
- `PUT` — полная замена ресурса;
- `PATCH` — частичное обновление ресурса;
- `DELETE` — удаление ресурса.

В разработанном API используются JSON-ответы, корректные HTTP-статусы и единый формат ошибок. Авторизация работает через cookie-сессии `express-session`, поэтому клиентская часть может использовать уже существующий механизм входа пользователя.

## 4. Описание разработанного REST API

В качестве основных REST-ресурсов выбраны:

- `products` — товары;
- `categories` — категории;
- `suppliers` — поставщики;
- `supplies` — поставки;
- `cart` — корзина пользователя;
- `orders` — заказы;
- `profile` — профиль пользователя;
- `auth` — авторизация и регистрация.

Требование CRUD и фильтрации выполняется на `products`, `categories`, `suppliers` и `supplies`. Для товаров используется идентификатор `article`, например `/api/products/SEED-001`. Для категорий, поставщиков, поставок, корзины и заказов используется числовой `id`.

Все endpoints под `/api/*` возвращают JSON. Пароль и password hash не возвращаются клиенту. SQL-запросы выполняются через параметризованные запросы PostgreSQL.

## 6. Описание фильтрации товаров

Endpoint `GET /api/products` поддерживает query-параметры:

- `search` — поиск по названию, описанию и артикулу;
- `category` — фильтрация по категории, включая дочерние категории через рекурсивный SQL-запрос;
- `inStock=true/false` — фильтрация по наличию;
- `sort` — сортировка: `name_asc`, `name_desc`, `price_asc`, `price_desc`, `popularity_asc`, `popularity_desc`;
- `page` и `limit` — пагинация.

Ответ имеет структуру:

```json
{
  "items": [],
  "meta": {
    "total": 0,
    "page": 1,
    "limit": 24
  }
}
```

## 7. Описание клиентской части

Клиентская часть была адаптирована для работы через REST API:

- страница `/catalog` загружает товары через `fetch('/api/products?...')`;
- поиск, сортировка, фильтр категории и фильтр наличия меняют query-параметры API;
- добавление товара в корзину выполняется через `POST /api/cart/items`;
- страница `/cart` удаляет позиции через `DELETE /api/cart/items/:id`;
- админская страница для товаров, категорий, поставщиков и поставок использует REST API для `POST`, `PATCH` и `DELETE`.

При ошибках API клиент показывает пользователю понятное сообщение, полученное из поля `error` JSON-ответа.
